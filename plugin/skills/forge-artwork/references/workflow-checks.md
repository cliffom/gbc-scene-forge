# Representative briefs and observable checks

Use these as task examples and evaluation cases, not mandatory output templates.
All work uses a selected disposable project for testing. A synthetic tool replay
establishes data/guard behavior; it does not establish model adherence, artistic
quality or image visibility. For an actual authoring run record the client/version,
exact candidate revisions, images actually inspected, refinements and saved result.

| Brief | Expected decisions and observable checks |
| --- | --- |
| “Draw a transparent 32×32 lantern sprite, warm gold light and dark blue metal; save it.” | Use general sprite geometry, deterministic pixel batches and an early render. Inspect silhouette, light and transparent edge pixels at native/enlarged scales; refine observed defects. Review the final candidate, commit, reopen exact saved pixels. No external service or hardware budget is required. |
| “Make a 160×96 dusk island illustration with separate sky and foreground layers; show a draft.” | Choose a static sprite document with named sources. Use dense patches where appropriate; inspect the full composition plus native details. Keep it unpublished and editable. Do not mistake a receipt or retained sidecar for a save. |
| “Create four 8×8 grass tile variants with one palette; keep them separate.” | Create a tile sheet with explicit frame rectangles and no sequences. Inspect edge repetition and every tile; preserve exact RGBA. Valid tile geometry does not establish seamless tiling or GBC runtime fit. |
| “Only recolor this sprite's scarf; leave its face, hidden sketch layer and other frames alone.” | Open fresh content, identify the intended source/region and colors, read affected pixels, patch narrowly. Compare exact other-source pixels/descriptors before/after, including hidden RGB; inspect a composite change overlay and scarf details. Do not quantize the whole palette. |
| “Animate a two-pose 8×8 beacon: glow for 120 ms, dim for 240 ms, looping. Save it.” | Use stable frame IDs, explicit durations/order/looping, PNG contact inspection and APNG review. Inspect loop continuity; report playback limits honestly. Reopen and verify native frames and timing after guarded save. |
| “Hold the second frame of Walk for 333 ms; preserve the other animation.” | Read fresh descriptor; change only that entry in complete canonical arrays. Pixels, frame IDs/origins and other sequence remain exact. Timing edit invalidates the earlier receipt; stale save must fail, fresh review/save succeeds. |
| “Change only the left-hand tree in my scene; the others share the same art.” | Identify explicit placement scope. Handoff to browser's selected-placement variation flow in this profile; do not edit the shared original or invent a hidden duplication call. Inspect affected replacements and unchanged source/other placements. |
| “Clean noisy pixels but protect the stars; use a four-color target if it fits.” | Discover available tools. This profile lacks automatic cleanup/conversion. Offer supported manual region edits/browser review and explain the limit; never label small islands as defects automatically. If a verified fuller inventory is available, use explicit protection/selected proposals, validation and image inspection; disclose literal color limits versus target/runtime estimates. |
| “Continue the returned browser draft from yesterday.” | Start with status/inventory/candidate discovery; retain `owner`. Compare exact current content and saved bases. Preserve conflicts instead of changing base hashes; inspect a fresh PNG, then review and save only within the requested scope. |

Failure checks: missing image visibility leads to a disclosed review handoff;
APNG without playback leads to PNG/order/timing inspection with a cadence limit;
unavailable tools lead to a supported fallback; stale bases/receipts reject before
publication; quota exhaustion preserves existing work. No check may discard
unrelated candidates, repair the plugin cache or broaden filesystem access.
